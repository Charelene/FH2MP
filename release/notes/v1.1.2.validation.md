# 1.1.2 release preparation

Prepared on 2026-10-28. No tag, publication or production rollout has been made.

## Included

- Azimuth 1.0.3 executable and numbered TLS-helper hashes from the supplied official archive.
- Official Extra Options 0.3.9 and Mod Platform 2.7.4 ZIP/DLL pins; complete EO plugin resources and both platform loader names.
- Authenticated multiplayer headlight/indicator/hazard state, with the corrected native target-car key lookup.
- Setup revision 2 for the new dependency combination, preserving installation preferences and saves.
- Production minimum launcher/shim 1.1.2, and rollout application/verification of the exact Azimuth compatibility metadata.
- Server deployment includes lighting.py. The existing release CI and publisher include the lighting checks.

## Evidence and remaining gates

The user confirmed the corrected feature in the real two-client dev session.
Both clients ran the actual lighting controls; no game input was automated.
Earlier automated runs passed 454 portable server checks and isolated native
lighting checks. The launcher run had 239 passes and 2 skips (241 checks). Those results predate the final
receiver-key correction and this version bump. They are not a final 1.1.2 CI pass.

At the user's request, no test suites were rerun during release preparation.
Changed Python sources were parsed, release shell scripts checked for syntax,
and the updated native test harness checked for C syntax without executing it.
Release shim and Linux launcher packages were rebuilt. The updated receiver
fixture uses opaque message context and the key stored on the native object;
its diagnostic logging stubs are included for the next CI run.

Public Windows and Linux builds and all required CI gates must pass before
publication. Local Linux packages are previews built on the development host;
the public assets should come from the release workflow. Exact blink phase,
pop-up-headlight animation and the experimental TCP-only fallback are not
expanded by this release; the lighting channel uses UDP and native blink timing.

## Existing release path

`release/notes/v1.1.2.deploy.sh` shows the plan only. Once the reviewed source is
committed and publication is authorized, the same command with `--execute` uses
ops/ship.sh -> release/publish.sh -> tag CI -> ops/release-prod.sh. Existing release
checks and explicit tag confirmation remain in place. Execution restarts production
services and requires a published, signed manifest with all Windows/Linux assets.
